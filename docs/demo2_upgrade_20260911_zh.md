# Demo2 本地体验与视频核对改进

日期：2026-09-11

## 本次范围

围绕教师上传课程后核对学生的工作流，改进上传任务管理、身份确认、画面查看与重复请求性能。保留课程、学生档案、教师复核、报告、会员和管理员的既有入口与权限。本次不引入外部模型服务，不上传课堂资料到第三方，也不改变原有保留期限。

## 教师操作路径

1. 登录后确认学校信息，进入课程上传工作台。
2. 上传并等待分析完成；通过关键词和任务状态查找当前账号有权查看的任务。
3. 打开视频回看，选择需要核对的时间片段；需要重复观察时启用当前片段循环。
4. 进入学生身份确认，放大采样画面，选择候选人脸或手动框选，再由教师对应到本校名册。
5. 采样画面不够清楚时，打开“原片彩色高清参考”。关闭参考后回到原采样帧操作。
6. 分别查看当前帧记录与全部历史；误认时撤销相应记录并填写原因。

## 画面与身份边界

- 原片参考从授权视频按指定时间解码，输出彩色 JPEG，最长边不超过 1920 像素，不放大源图，也不是超分辨率修复。
- 旧采样帧经过定频采样与缩放，参考图按相近时间重新解码，两者不保证逐帧相同。因此参考弹窗只读，不沿用旧框，也不能在其中保存身份。
- 自动定位提供候选人脸位置；学生姓名仍由教师确认。当前确认范围为单张采样帧，不宣称连续跨帧跟踪或跨学校自动身份识别。
- 未确认学校归属的旧任务必须先由有权教师确认；系统不猜测学校，也不以同名自动合并档案。

## 性能与资源控制

| 项目 | 当前实现 | 边界 |
|---|---|---|
| 采样帧清单 | 缓存校验通过的解析结果 | 最多 8 个清单、共 40,000 条帧记录；清单或源校验记录变化后重新校验 |
| 人脸候选结果 | 成功结果最多缓存 120 秒 | 最多 128 项、序列化内容最多 2 MiB；缓存按账号、任务、帧版本及文件版本隔离 |
| 彩色参考 | 最多缓存 60 秒 | 最多 16 项、图像内容总量最多 64 MiB；没有新增磁盘缓存 |
| 解码控制 | 单进程内串行解码；冷请求限频 | 单次 JPEG 最多 4 MiB，媒体子进程使用共同超时预算 |
| 请求授权 | 命中缓存也重查访问权限、帧版本和源视频到期状态 | 缓存不保存登录许可或学校访问权限；HTTP 使用 private/no-store |

上述字节限制是缓存有效载荷限制，不是整个 Python 进程的内存上限。媒体处理设置 8 秒共同截止预算，但底层文件系统或进程启动的异常阻塞不能保证硬实时。多进程部署仍需统一队列、全局限流和宿主资源限制。

缓存过期采用访问时惰性清理，不代表内存副本恰在该秒被物理清除；对用户的每次访问仍实时执行视频保留期限检查。检测和参考画面在计算完成后再次校验权限与帧版本，失效结果不发送、不写入缓存。

## 界面取舍

维持蓝白主色，使用中性色组织课程和表单，仅用绿色、琥珀色、红色表达成功、待处理和错误。缩小工作台标题与装饰面积，将视频和实际操作置于主要区域。字体优先使用本机中文 UI 字体，未引入外部字体或第三方脚本请求。

参考的是成熟工具的操作组织，而非复制其视觉页面：

- [CVAT 画面控制与缩放](https://docs.cvat.ai/docs/annotation/annotation-editor/controls-sidebar/)
- [Seesaw 按学生及活动复核](https://help.seesaw.me/hc/en-us/articles/27160258738957-How-to-approve-posts-individually-and-in-bulk)
- [Fluent 等待与进度反馈](https://fluent2.microsoft.design/wait-ux)

## 验证记录

功能测试使用隔离的合成数据，不替教师修改真实学生身份。真实课程仅用于经过登录的只读查看与耗时测量；登录和查看仍会产生必要的会话与访问审计记录。

本次分批执行的相关测试，按测试文件去重计 873 项通过、3 项跳过：

| 范围 | 通过 | 跳过 |
|---|---:|---:|
| 上传/API、媒体访问、私有网关、身份安全、异常诊断、会员安全 | 374 | 0 |
| 身份 API、结果缓存、升级后的接口契约 | 144 | 0 |
| 身份存储与清单缓存 | 180 | 1 |
| 身份、上传、登录和回看界面 | 107 | 0 |
| 原片参考解码 | 68 | 2 |

跳过项为 Windows 实际符号链接创建权限相关用例；不等同于所有部署环境都已验证。桌面/手机实际页面 14 组检查通过，产出 18 张 PNG；无页面 JavaScript 错误、HTTP 错误、页面横向溢出或损坏图片。合成浏览器测试另覆盖教师确认/撤销、缩放后的框坐标、预览取消、任务筛选与原生片段循环。

### 本地耗时对照

在同一台电脑、同一份约 37 分钟课程录像、同一张采样帧上，以教师和管理员分别请求每个接口 3 次，以下为中位数。升级后教师定位及参考图先经过一次版本预检，属于暖缓存；管理员定位包含一次冷请求与两次缓存命中。这不是多用户压测，也不代表首次推理或识别准确率。

## 尚未完成的能力

本次没有训练新的状态识别模型，也没有验证真实课堂的识别准确率。人脸候选仍可能漏检；自动跨帧追踪、经教师核准的姓名连续关联、课程语音与学生互动归因，仍需要独立实现与真实标注评测。缓存加速不能作为算法准确性提升的证据。
