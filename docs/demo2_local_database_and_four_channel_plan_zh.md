# RehabAffect Demo2 本地数据库与四路视频上传规划

版本日期：2026-08-26  
适用范围：辅读学校课堂学习证据、个体化支持、教师复核和后续具身动作接口

## 1. 结论

当前产品适合采用“本地先跑通、校内服务器试点、再迁移学校独立云空间”的三阶段路线。

- 当前版本使用 SQLite 保存学生资料元数据、结构化支持摘要、四路上传任务、保存策略和审计记录。
- 学生 IEP、五大领域、专业评估和安全支持资料通过独立页面上传；原文件与结构化摘要分开保存。
- 四个上传端口按产品概念定义为同一平台内的四个上传通道，不是四套系统，也不是四个 TCP 端口。
- 每个通道拥有独立上传主体、课程、观察对象、任务编号、进度、结果和下载入口。
- 相同 `session_id` 的四段视频可以在获得授权后做时间对齐和多视角融合；默认互不共享结果。
- 当前本地版在视频上传完成后生成完整性与画面质量预检。学生课堂状态结论仍需绑定课程目标、学生身份/座位区域并由教师复核。

## 2. 本次已落地能力

### 2.1 学生资料导入

- 选择当前学生后上传 IEP、五大领域、专业评估、行为指导或安全支持资料。
- 支持 DOCX、PDF、Excel、CSV、JSON、TXT、PNG、JPG，单文件上限 10MB。
- 保存原始文件名、文件类型、来源单位、资料日期、说明、文件大小、SHA-256、上传时间和到期时间。
- DOCX、TXT、CSV 和 JSON 可生成文本预览；其他类型保存原件并要求教师填写结构化摘要。
- 结构化摘要包含已有专业结论、IEP/教育目标、已验证支持方式、刺激禁忌与安全边界、确认人和更新时间。
- 系统不根据上传资料推断医学诊断，也不根据障碍类别直接降低学习目标。

### 2.2 数据存储管理

- 页面显示 SQLite 数据库、学生资料目录和课程报告目录的真实本机位置。
- 显示学生数、结构化档案数、视频任务数、数据库大小和审计记录数。
- 对原始音视频、学生原文件、课程报告和脱敏结构化档案分别设置保存天数。
- 默认原始音视频保存 60 天，可由管理员调整为 30、60、80、90 天或其他经校方确认的周期。
- 已登记资料可以下载和删除；删除文件的操作进入审计日志。
- 页面明确显示“云端尚未配置”，不把未来云端能力当成当前能力。

### 2.3 四路视频上传

- 固定提供四个独立上传通道，每个通道可由不同教师、班级、设备或其他获授权主体使用。
- 每个任务记录上传主体、课程、课堂批次号、观察对象、文件名、大小、通道和到期时间。
- 浏览器按 4MB 分片上传，单文件上限 5GB；四个通道可以分别发起任务。
- 上传完成后计算 SHA-256，并对视频进行可读性、时长、帧率、分辨率、亮度、清晰度和运动量预检。
- 每个通道独立生成 JSON 结果并提供下载。
- 预检结果只判断视频是否适合进入后续分析，不直接输出学生“学会/不会”或医学结论。

## 3. 产品工作流

### 3.1 学生资料工作流

1. 教师选择学生并确认资料授权范围。
2. 上传原文件，系统记录文件元数据、哈希和保存期限。
3. 系统提取可读取文本作为预览，不自动把文本解释为诊断。
4. 教师填写并确认结构化支持摘要。
5. 摘要进入学生个体支持档案，参与提示方式、安全边界和机器人动作约束。
6. 后续课程只引用有效版本；更新和删除均保留审计记录。

### 3.2 四路视频工作流

1. 四个主体分别登录或进入各自上传通道。
2. 选择课程、观察对象，填写同一课堂批次号或各自独立批次号。
3. 浏览器分片上传，服务端校验顺序、大小和文件哈希。
4. 任务进入质量预检；正式版随后进入 CPU/GPU 分析队列。
5. 每个通道独立显示任务状态、失败原因、到期时间和结果下载入口。
6. 同批次视频经过授权后进入时间戳对齐、人物/座位绑定和多视角融合。
7. 教师复核关键片段后形成课程报告、个体记录和下一步支持动作。

## 4. 本地数据库总体设计

### 4.1 当前技术形态

- 结构化数据：SQLite 3，默认文件为 `outputs/seewo_demo2/rehab_affect_demo2.sqlite3`。
- 学生原文件：`outputs/seewo_demo2/student_documents/`。
- 四路视频任务：`outputs/seewo_demo2/video_tasks/`。
- 报告：`outputs/seewo_demo2/reports/`。
- 当前 JSON 分析结果继续保留，用于兼容已有 Demo；新上传和治理数据逐步进入 SQLite。

### 4.2 分层原则

- 身份层：学校、账号、角色、班级、学生匿名编号。
- 教育资料层：IEP、五域评估、专业资料、结构化支持摘要及版本。
- 课程层：课程、课堂批次、教学目标、考核标准和四路视频。
- 分析层：任务、模型版本、证据窗口、状态初评、学习机会和置信度。
- 人工判断层：教师复核、正确性、提示等级、画面外信息和定稿结论。
- 行动层：教师支持建议、屏幕/语音/机器人动作、确认与执行结果。
- 治理层：保存策略、访问日志、下载、删除和授权状态。

### 4.3 核心表规划

| 表 | 作用 | 当前状态 |
| --- | --- | --- |
| `schools` | 学校与数据隔离边界 | 全校版新增 |

| `students` | 学生匿名编号和基本档案状态 | 已实现基础表 |
| `student_documents` | IEP、五域、专业资料原文件元数据 | 已实现 |
| `student_support_profiles` | 教师确认的结构化支持与安全摘要 | 已实现 |
| `support_profile_versions` | 支持档案历史版本与生效区间 | 试点版新增 |
| `courses` | 课程名称、目标、标准和考核口径 | 现有 JSON，待迁库 |
| `class_sessions` | 一节课的统一 `session_id` 与时间范围 | 试点版新增 |
| `video_upload_channels` | 四个上传通道配置与主体范围 | 已实现 |

| `retention_policies` | 分类保存周期、是否自动删除 | 已实现 |
| `audit_logs` | 上传、查看、修改、下载和删除留痕 | 已实现基础表 |

### 4.4 关键关联

`school -> student -> support_profile/document`  
`school -> course -> class_session -> four video tasks`  
`video task -> analysis run -> evidence windows -> teacher reviews -> report`  
`evidence window -> recommended action -> teacher confirmation -> robot execution feedback`

这条链路与产品的具身智能闭环一致：Perception -> State Estimation -> Action Suggestion -> Teacher Confirmation -> Robot Action -> Feedback。

## 5. 保存周期建议

| 数据类型 | 默认周期 | 可配置范围 | 到期动作 | 说明 |
| --- | ---: | ---: | --- | --- |
| 原始课堂视频/音频 | 60天 | 30/60/80/90天 | 提醒后删除或经审批延长 | 高敏感、大容量 |
| 自动生成临时切片 | 30天 | 7-60天 | 自动删除 | 报告定稿后通常无需长期保存 |
| IEP/专业评估原文件 | 365天 | 180-730天 | 管理员复核 | 应与学校授权和资料有效期一致 |
| 脱敏结构化支持档案 | 730天 | 365-长期授权 | 版本化保留 | 用于跨课追踪，撤回授权时删除 |
| 教师复核记录 | 365天 | 180-730天 | 归档或删除 | 是模型校准和报告定稿依据 |
| 课程与个体报告 | 365天 | 180-730天 | 可下载后归档 | 报告与原视频使用不同周期 |
| 审计日志 | 365天 | 365-1095天 | 归档 | 用于追踪访问、下载和删除责任 |

保存周期不能由研发单方面确定。学校需要确认数据是否允许离校、监护人授权、人员离职后的权限处理、到期提醒天数和删除审批人。

## 6. 四路视频的硬件条件

### 6.1 上传端

- 每个主体可以使用普通 Windows 办公电脑，不要求本地 GPU。
- 建议 CPU：Intel Core i5 / AMD Ryzen 5 或以上。
- 内存：最低 8GB，建议 16GB。
- 浏览器：较新版本 Chrome 或 Edge。
- 本地临时空间：每台至少保留 20GB。
- 单路稳定上行带宽：最低 5Mbps，建议 10Mbps 以上。
- 四路同时上传：建议学校总上行 40Mbps 以上；校内服务器方案优先使用千兆局域网。

### 6.2 采集端

- 建议 1080p、H.264、15-25fps、3-5Mbps。
- 固定机位、稳定支架，画面覆盖目标座位和主要教学区域。
- 远场语音质量不足时，教师端可增加领夹麦或指向麦；不能保证说话人时不绑定具体学生。
- 四台设备应启用系统自动校时；同一课堂建议开拍时加入可见/可听同步事件。
- 不要求一开始采购机器人、智能坐垫或专用摄像头。

### 6.3 试点服务器

- CPU：8核或以上。
- 内存：32GB。
- 存储：1TB NVMe SSD 起步，建议加密和每日备份。
- GPU：仅做上传、数据库和报告时不必配置；需要本地多路视觉推理时建议 12-24GB 显存。
- GPU 参考层级：RTX 4070 Ti Super/4080 适合试点推理，RTX 4090 或同级云 GPU 适合更高吞吐实验。
- 正式全校并发量确定后再做容量压测，不按演示机器配置直接采购。

### 6.4 容量估算

30分钟、3-5Mbps 的 1080p H.264 视频约为 0.68-1.13GB。四路合计约 2.7-4.5GB/节课。

若每天分析2节课、原视频保存60天：

- 原视频约 324-540GB；
- 加上约30%的数据库、切片、报告和运行余量后约 421-702GB；
- 因此单校试点建议从 1TB 可用存储开始，并在实际码率和课程量确定后调整。

## 7. 软件条件

### 7.1 当前本地版

- Python 3.10+；
- SQLite 3；
- OpenCV 用于视频读取和质量预检；
- Chrome/Edge 浏览器；
- 本地 HTTP 服务和受控文件目录；
- 无需云账号即可演示。

### 7.2 校内试点版

- Web API 建议迁移到 FastAPI；
- PostgreSQL 保存业务数据；
- MinIO 或学校对象存储保存视频和资料原文件；
- Redis + Celery/RQ 管理四路异步任务；
- Nginx/HTTPS、账号登录、角色权限和访问日志；
- FFmpeg 做统一转码、音轨提取、分片和时间戳处理；
- CPU/GPU 推理工作节点与 Web 服务分离。

### 7.3 云端或多学校版

- 每所学校独立租户与对象存储前缀；
- PostgreSQL 行级/租户级隔离；
- 对象存储服务端加密和临时下载链接；
- GPU 任务按队列弹性扩容；
- 自动到期任务、审计报表、备份恢复和安全告警；
- 不允许不同学校互相查看学生、视频或报告。

## 8. 部署阶段

### 阶段A：本地产品验证

- 使用 SQLite 和本地目录；
- 验证资料字段是否够用；
- 验证四个主体能否独立完成上传、查看进度和下载结果；
- 验证教师复核时间和页面易用性。

### 阶段B：学校内网试点

- 部署一台校内服务器；
- 接入账号、角色、PostgreSQL、MinIO、任务队列和 HTTPS；
- 选择一个班级、2-4节课做影子测试；
- 不直接用于学生干预或教师考核。

### 阶段C：全校服务

- 按班级、课程、学生和角色扩展；
- 接入云端或校级数据中心；
- 引入经过教师标注验证的多模态模型；
- 形成跨课趋势、全校报告和机器人/屏幕动作接口。

## 9. 校方仍需确认的问题

1. 四个主体具体是四名学生、四名教师、四个班级、四台设备，还是四个摄像机视角？
2. 四段视频是否通常属于同一节课，是否需要自动同步和融合？
3. 每段视频的典型时长、分辨率、码率、文件格式和每天上传数量是多少？
4. 四路是否会同时上传，学校实际上行带宽和校内网络条件如何？
5. 每个主体可以查看哪些学生、哪些课程和哪些结果，管理员由谁担任？
6. 校方要求下载的是质量预检、学生状态分析、课程报告、教师复核表还是全部结果？
7. 原视频、IEP、结构化档案和报告分别保存多久，是否允许离开学校？
8. 到期删除由系统自动执行还是由管理员审批，是否需要提前7天或15天提醒？

## 10. 验收标准

- 四个通道可以各自创建任务，不发生文件、身份和结果串线。
- 1GB以上视频可以分片上传，失败后能明确提示；试点版需增加断点续传。
- 每个任务均有唯一编号、上传主体、课堂批次、文件哈希和到期时间。
- 上传完成后生成可下载的结果文件；完整课堂结论必须标记模型版本和教师复核状态。
- 学生资料原件、结构化摘要和课堂证据能够关联，但权限和保存周期相互独立。
- 上传、查看、下载、修改和删除均可追溯。
- 未经授权的账号不能访问其他主体、班级或学校的数据。
- 系统继续坚持不做医学诊断、不替代教师判断、不把单次动作直接解释为学会或不会。
