# RehabAffectPerception 多任务协作约定

## 1. 主任务

当前“RehabAffect｜主控与集成”作为主任务，负责：

- 接收需求并判断优先级；
- 拆分技术任务并指定负责岗位；
- 维护跨模块的数据和接口契约；
- 审查各任务产出，处理冲突并完成最终集成；
- 统一运行完整测试、启动演示和整理交付物。

公司的产品主线是辅读学校课堂学习支持与学生追踪平台。MuJoCo benchmark 属于个人实验资产，保留现状，但不进入后续公司功能、排期和交付范围。

## 2. 长期岗位

### 前端开发

负责教师端页面、课程工作台、四路上传、分析进度、群像与学生个体页、教师复核、报告、档案和存储治理页面。负责响应式、可访问性、视觉回归和前端组件拆分，不修改模型规则和数据库结构。

### 后端开发

负责 API、身份认证、业务服务、课程分析任务编排、分片上传接口、报告生成接口、WebSocket 和机器人动作输出接口。通过数据库任务提供的仓储接口访问数据，不直接决定模型标签和页面视觉。

### 数据库与存储

负责学校、班级、课程、学生、IEP、视频、标注、报告和审计数据模型；负责 SQLite 到 PostgreSQL 的迁移、对象存储、60 天保留、到期提醒、备份恢复和脱敏。不得在未协商时修改前端或模型逻辑。

### AI 模型与数据

负责视频与音频预处理、人物追踪、姿态和动作线索、VAD/ASR、师生互动匹配、时序融合、掌握度模型、训练数据、评估和模型服务接口。输出必须区分可观察证据、模型推断和证据不足，不做医学诊断。

### 测试与发布

负责单元测试、API 集成测试、数据库迁移测试、Playwright 端到端与视觉回归、性能与安全边界检查、发布清单和回归报告。原则上不直接修改业务实现，发现问题后交回对应岗位修复。

## 3. 共同接口

跨岗位变更优先围绕以下契约协作：

1. 课程批次与课程标准；
2. 学生档案、IEP 和支持约束；
3. 视频上传任务及处理状态；
4. 教师复核片段和结构化标签；
5. `human_state`、掌握度和课程报告；
6. 经教师确认的 `robot_action` 与执行结果。

接口契约由主任务确认后再分别实施。任何岗位不得单方面更改其他岗位已经依赖的字段含义。

## 4. 开发规则

1. 每个任务开始前由主任务明确目标、输入、输出、写入文件范围和验收命令。
2. 同一时间不允许两个任务修改同一个源文件。
3. 当前仓库存在未提交改动，所有任务必须保留已有修改，不得执行破坏性回退。
4. 岗位任务完成后只报告修改文件、接口变化、测试结果和剩余风险，由主任务决定是否集成。
5. 完整回归、演示启动和交付打包只由主任务统一执行。
6. 新需求优先派给下面五个既有岗位任务，不以临时后台子任务替代，也不重复新建岗位。主任务检查任务状态后下发目标、文件边界与验收要求。
7. 岗位之间不能直接通信时，由主任务转达接口变化和阻断项。用户只需在主任务提出需求和查看最终成品。

## 5. 推荐代码演进边界

当前页面、API、分析逻辑仍集中在少数大型 Python 文件中。后续按岗位逐步拆分为：

```text
frontend/              独立 Web 前端
src/rehab_affect/api/  HTTP API 与鉴权
src/rehab_affect/services/ 课程、上传、分析和报告服务
src/rehab_affect/models/   多模态模型与推理适配
src/rehab_affect/storage/ 数据仓储与对象存储
src/rehab_affect/contracts/ 共享 JSON 契约
tests/unit/            单元测试
tests/integration/     API、数据库和模型集成测试
tests/e2e/             页面端到端测试
```

目录调整采用渐进迁移，先加兼容层和测试，再移动现有实现，避免一次性重写导致 Demo2 失效。
