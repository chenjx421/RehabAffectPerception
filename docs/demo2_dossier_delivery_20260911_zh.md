# Demo2 学生档案关联与资料治理

日期：2026-09-11。当前状态：五个固定任务开发及主控集成完成，本机服务已更新；7页图文PDF已生成并完成逐页检查。

## 本轮交付范围

本轮解决的是“同一个学生的视频、IEP和专业评估资料如何正确对应，以及公司究竟可以保存和查看什么”，不新增疾病推断、模型训练或医学判断。课堂视频仍是视频文件；IEP与评估资料是独立文件及结构化摘要，不会被转换成视频留存。

新资料沿用新版学生名册的唯一 student_id，关联上传账号和学校范围；同名不代表同一个人。视频中人物仍须由教师确认，不能由姓名相似度或病症猜测身份。新档案与旧全局案例库不自动合并；原有文件保留原位，后续经授权与身份核对后才可重新导入。

## 教师使用流程

1. 登录学校上传账号，核对城市、区县和学校，进入学生名册。用编号和班级区分同名学生。
2. 打开该学生的“资料档案”，登记授权依据编号、处理方式与截止日期。当前版本的处理目的限定为教育支持，不包含训练和公司长期资源归档。教师确认仅记录其核对行为，不代替学校应具备的实际授权材料。
3. 选择资料类型：IEP、专业评估、五大领域评估或安全与支持说明。填入材料日期和来源编号，按需录入学习目标、支持方式、安全注意事项及原材料已有的专业结论。没有专业结论就留空，系统不补造诊断。
4. “仅摘要”模式不上传原件；“原件与摘要”模式可以选择原件。原件是可选的，至少有一项有效摘要或原件。不得以“摘要”名义录入不必要的完整病史。
5. 新材料作为新版本保存，不能覆盖以前的IEP。每个版本单独记录来源、日期和期限。
6. 在已处理视频中确认学生姓名后，进入“课堂资料引用”，选择本节课适用的材料版本并确认。引用记录关联课程、视频来源、采样版本、学生和教师确认的画面记录。
7. 下载课堂资料引用记录，用于复核本次分析所依据的材料。后续新增IEP不会自动改写旧引用；材料失效或人员确认被撤回时，导出必须明确标示不可用。

## 数据如何存放

| 内容 | 保存方式 | 访问边界 |
| --- | --- | --- |
| 学生名单与视频中的确认记录 | 现有本地SQLite学生名册、视频任务与人物确认表 | 按上传账号和学校范围校验 |
| 新授权依据、来源说明、摘要、原始文件名 | 新档案表内的加密数据 | 仅对应学校上传账号；公司管理员不读取正文 |
| 可选原件 | 本地独立目录中的加密文件，数据库保存内部关联 | 不提供公开静态文件地址；下载接口重新验证权限和期限 |
| 课堂引用 | 版本编号、课程与视频证据标识 | 不复制一份永久有效的敏感摘要；导出时重新检查原资料 |
| 公司运维汇总 | 数量、有效/到期/待删除状态与字节数 | 不含学生姓名、诊断结论、原件名或授权依据正文 |
| 最小审计留痕 | 操作类型、内部编号、状态与时间 | 不记录摘要正文；不能将留痕理解为永久保存敏感资料 |

加密范围限本轮新增资料，不代表旧SQLite数据库、历史视频、学生名册和备份已全面加密。Windows默认使用当前运行用户的DPAPI保护档案密钥；跨机器或更换服务账号必须另行设计密钥迁移和恢复方案，不能只复制数据库就宣称可恢复。Linux等环境必须配置有效密钥，缺失或损坏时关闭敏感资料功能，不回退明文。

## 期限、撤回与删除

- 本轮新增资料按明确日期保存，授权和材料期限均不超过60天的试点上限，可更短。60天是当前产品约束，不是法律规定的统一保存期。
- 新资料期限不能超过对应授权期限，不能借上传新版本自动延长旧版本。
- 到期、撤回授权或主动删除后，接口停止提供敏感内容；后台清理原件与敏感字段。文件删除失败应标记“待删除”，阻止访问并重试，不能报称已彻底删除。
- 删除后的引用仅保留必要的关联状态，不从其他副本恢复失效摘要。
- 已下载到使用者电脑的报告、磁盘快照、旧备份和人工复制件，不在本轮自动清理范围内，需要组织层面的分发与删除管理。
- 视频原有期限与新增资料期限分别执行；不能因为视频到期就假定所有IEP已删除，也不能因为IEP有效就延长视频期限。

## 不应对外承诺的事项

1. 这不是公司已经获得了学校全量资料的永久使用权；页面确认也不是监护人电子签名系统。
2. 这不是全校统一跨教师档案。当前同校不同上传账号仍隔离，正式多人协作需要学校管理员授权与班级人员权限模型。
3. 课堂引用是可追溯的证据关联记录，不意味着已有千字报告自动读取新档案、完成医学解释或提高了识别准确率。
4. 当前不向外部LLM发送新增敏感资料，不把IEP、专业评估或视频自动加入训练集。
5. 加密与接口鉴权是技术措施，不等于生产安全审计和合规验收已经完成。
