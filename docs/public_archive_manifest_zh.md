## 归档范围

本次归档面向 GitHub 版本管理，目标是让电脑格式化后仍能恢复 Demo1-Demo2 的源码、配置、测试、部署模板、版本说明和已筛选的 PDF。

已纳入：

- `src/rehab_affect/`：当前脱敏后的累计源码；
- `tests/`：单元测试、接口测试和验收测试；
- `configs/`：标签、场景、知识配置和策略模板；
- `scripts/`、`deploy/`、启动文件和项目配置；
- `deliverables/` 中可公开的历史源码交付目录；
- `docs/version_pdfs/` 中按版本归档的 PDF；
- `docs/demo_version_catalog_zh.md`、`docs/github_versioning_plan_zh.md` 和 `docs/doc2_gap_check_zh.md`。

## 有意排除的内容

以下内容不进入 GitHub：

- 账号密码、API Key、私钥、Cookie、邀请密钥和真实服务器控制凭据；
- 真实数据库、SQLite 文件、视频、音频、IEP 原件、诊断资料和人脸原图；
- `.runtime/` 中的部署状态、云端密钥、真实任务结果和内部运行截图；
- 未经筛选的 `output/`、`tmp/`、`work/` 和模型缓存；
- 含真实公网 IP、临时隧道或登录信息的原始交付 PDF。

部分功能展示 PDF 保留了当时的页面截图，用于版本回溯；它们不是生产数据，也不代表最终云端一定启用截图中的全部入口。

## 格式化电脑后的恢复

```powershell
git clone https://github.com/chenjx421/RehabAffectPerception.git
cd RehabAffectPerception
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[test]"
$env:PYTHONPATH='src'
python -m pytest -q
```

需要运行平台 Demo 时，再按 `README.md` 和 `deploy/` 中的模板配置本机私有环境变量。GitHub 归档可以恢复源码和公开文档，但不能恢复未公开的真实数据库、视频、学生资料、账号密码或云端运行状态。

## 版本真实性说明

原仓库只有 2026-06-04 的初始化提交，没有 V01-V24 的连续 Git 历史。因此 V01-V24 是根据源码包、交付材料、测试记录和文件日期重建的版本索引，不伪造不存在的历史提交。云端正式发布只保留 `cloud-final-v3.2-20261022`；V21、V22、V24 作为研发或测试证据归入 V23。
