# Demo2 人员确认与通道管理

日期：2026-09-11

## 教师的操作路径

登录后进入课程上传工作台，打开对应视频的“确认画面中的学生”。常用操作为：

1. 选中画面中的一人：点击检测候选；没有候选时，点击“手动画框”，在画面上拖出矩形。
2. 选择本校学生姓名。名单中没有时，可在当前页“新增本校学生”，不需要离开画面重来。
3. 点击“确认姓名”。确认记录保存到本地数据库，刷新后仍能查看；需要修正时撤销原记录，再重新确认。

默认角色为学生。坐标、教师或未知人员角色放在高级选项内；普通姓名确认不必操作这些字段。同名学生通过校内编号、班级区分，不因姓名相同而合并档案。

## 漏检、遮挡和跟随

| 情况 | 操作与结果 |
|---|---|
| 人脸没有被检测到 | 手动画框不依赖检测成功；画面有效且有权限时，可直接保存人工确认 |
| 学生部分重叠 | 可框出各自可见区域；与已有框高度重叠时需教师再次确认，不覆盖另一条记录 |
| 两个框几乎完全相同 | 拒绝重复绑定到不同学生，应换清楚的时刻或分别框出可见部分 |
| 人物完全遮挡、无法辨别 | 不猜姓名，不声称能够“透过遮挡”识别；选择其他时刻核对 |
| 想查看后续位置 | 在已确认学生记录上选择“查看后续5秒”，逐帧查看短时位置建议 |
| 建议位置合适 | 采用为草稿后，再由教师确认姓名才保存；不会批量自动写入档案 |
| 跟丢、快速变化、相似人物干扰 | 停止建议，不自动重新接到其他人，教师重新选取清楚的画面 |

后续位置使用本地 OpenCV 稀疏光流，最多处理起始帧及后续五张采样帧；不是整节课连续追踪，也不识别姓名、情绪、病理或知识掌握度。低清晰度、小脸、缺少纹理、较大位移可能无法产生可用建议。需要教师逐条核对，不以跟随质量数值代替身份置信度。

## 按钮不可用时

- 旧视频没有学校归属：可以先框选草稿，但必须由教师核对并确认视频实际学校后才能保存姓名；确认学校后保留原框选草稿。
- 图片未加载、视频到期或访问权限不足：显示具体原因，不生成没有画面依据的确认。
- 公司管理员：只读查看人员确认。学生姓名与画面对应由所属学校账号确认，不由公司管理员代为猜测。
- 保存后网络中断：提示先刷新核对，避免重复创建或重复确认。迟到的检测结果不会覆盖已经画好的区域。

## 公司通道设置

公司后台的通道区域提供“管理上传通道”入口，管理员可以实际修改通道名称、负责人备注、每课程上传名额（3至5个），以及是否暂停新建上传。保存后重新读取数据库确认结果。

暂停只阻止新建上传，不影响历史视频、已开始任务的续传和分析。不删除数据，不更改学校归属、登录账号或密码。降低名额时若已有课程占用超限，会明确提示，不能通过降低名额删除历史任务。

多人同时编辑时，通过版本校验提示冲突；不会覆盖别人刚保存的配置。更改记录写入审计，包含修改前后值。

## 数据与能力边界

人员确认关联任务、画面版本、时间、区域、学生标识和确认人；需要重新处理或源文件变化时，旧确认不作为新版本的有效身份。短时跟随建议不新增学生档案或确认记录。

本次未改变保留期限，未引入第三方模型 API，也未将课堂资料上传到外部服务。服务仍为本机访问；功能测试使用隔离数据库及合成画面，不能把功能测试通过表述为真实学生识别准确率已验证。

本地入口：`http://127.0.0.1:8792/demo2/login`。老师操作人员确认，公司管理员操作通道设置。
