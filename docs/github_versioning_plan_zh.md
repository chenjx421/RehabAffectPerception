# RehabAffect Demo GitHub 逐版本推送方案

更新时间：2026-10-24

## 1. 这份方案解决什么问题

本项目没有从 Demo1 开始连续保存的 Git 提交，当前 Git 只有 2026-06-04 的初始化提交。因此不能把今天的工作区直接伪装成一串真实历史提交。本方案按现有源码包、交付包、文档、测试证据和云端留痕，建立一组**有证据等级的历史版本标签**。

`Doc2.docx` 只用于查漏补缺，不增加一个虚构的版本号；它截图中对应的能力回填到已有 V14、V15、V16、V17、V20 等版本。

## 2. 两条线要分开

### GitHub 历史线：逐版本保留

GitHub 按 V01 到 V24 逐步推送。每个版本保留当时能找到的源代码、配置模板、测试和说明；没有独立源码快照的版本，明确标记为“从累计源码或当前差异重建”，不能写成精确历史快照。

## 3. 每个 GitHub 版本必须带什么

每次推送前，在版本目录或版本说明中固定放置：

1. `VERSION.md`：版本日期、功能、源代码位置、证据等级、已知边界。
2. `SOURCE_MANIFEST.csv`：源码文件、用途、来源、是否可独立恢复。
3. `TEST_README.md`：启动命令、测试入口、通过项和未通过项。
4. `configs/*.example`：只放不含密钥的配置模板。
5. `tests/`：该版本实际存在的单元测试或验收脚本。
6. `SHA256SUMS.txt`：只对公开源码和说明文件计算，不对真实数据计算并公开。

不能放进公开历史版本：

- 学生真实姓名、IEP、诊断、评估资料和人脸截图；
- 真实课堂视频、音频、原始上传目录和分析结果数据库；
- `.runtime/` 内的云端配置、邀请密钥、账号密码、私钥和临时截图；
- API Key、访问令牌、Cookie、服务器密码和内部公网维护信息；
- `outputs/`、`work/`、`tmp/`、Playwright 临时目录中的真实测试产物。

## 4. 建议的逐版本推送操作

### 第一步：建立脱敏版本工作树

不要直接对当前混合工作区连续提交。先为每个 V 版本准备一个只含该版本源代码的目录，来自对应离线包、交付包或累计源码，并把运行数据、真实材料和内部配置移出。

### 第二步：先推 V01-V07

优先保留 Demo1 的核心证据，尤其是：

- 指定学生/目标区域；
- 学生状态时间轴；
- 时间窗状态证据；
- 课堂总结和支持建议。

这是后续解释“为什么 Demo1 的能力后来看起来消失”的基线，不能被 Demo2 的通用匿名人物结果覆盖。

### 第三步：推 V08-V20

按目录顺序逐步加入三学生 Demo2、多学生页面、媒体任务、身份、档案、评分、双轨评价、课程工作台、四通道和后台留存。每一版的新增文件和边界写入 `VERSION.md`，不要把后来代码倒灌回早期版本。

### 第四步：推 V21-V24

把云端候选、上传修复、人物结果、彩色证据帧和户外/高清测试作为后期历史记录。V21/V22 的候选包保留研发证据，V23 标为最终云端交付，V24 只作为 V23 的测试补充。

### 第五步：每版独立验收后再建标签

推荐顺序：

```text
脱敏 -> 源码清单 -> 语法检查 -> 单元测试 -> 启动检查 -> 页面/接口验收 -> SHA256 -> 建标签 -> 推送
```

如果某个版本无法独立启动，应标注“历史源码归档/不可独立部署”，不能用当前最终版本的页面截图替代该版本的源码证据。

## 5. 为什么之前的功能会出现“有过、后来没有”

1. Demo1 依赖固定学生区域和固定样例视频；Demo2 改成通用上传后，不能直接把固定 ROI 当成任意视频中的姓名识别。
2. 学生档案、IEP、教师核准和双轨评分后来成为高级模块，为先跑通上传主线而被移出必经步骤，但代码和文档并不代表每次云端发布都带上了它们。
3. 云端发布是筛选后的部署包，不是整个工作区原样复制；因此本地“存在”的模块可能没有进当时云端包。
4. 多模态或人物关联能力出现过不稳定结果，正式云端回退到本地解码、匿名人物候选和彩色证据帧。
5. 当前版本的 `simple_student_seats_v3_2` 只承诺匿名人物的活动和可见性线索，不能把 Demo1 的学生状态标签直接宣称为通用模型结果。
6. Git 没有连续历史，所以这次需要通过源码包和证据建立可追溯标签；标签本身不是原始 Git 历史的替代品，证据等级必须保留。

## 6. 这次查漏补缺的结论

`Doc2.docx` 中的 10 类页面功能已经能在版本目录中找到对应源码入口：档案授权、IEP 导入、课堂资料关联、学生测量、双轨评价、学校评价、系统增强评价、分差对照、图文报告和公司后台。它们分散在 V14-V20，不应被合并为一个“Doc2 版本”。

仍需要后续补齐或现场验证的部分：

- 真实资料授权后，人物与学生档案的结果页一键绑定；
- IEP 摘要与本课总结的稳定关联和撤销审计；
- 教师核准如何进入评分校准，而不是只作为一个页面入口；
- 特教课程权重的学校样本校准和近年文献复核；
- 云数据库、对象存储、备份恢复、并发队列和长期审计；
- GitHub 每个标签的独立脱敏源码目录和可复现启动检查。

本次归档采用“公开脱敏源码快照 + 版本目录”的方式提交。由于原仓库没有保存 V01-V24 的连续 Git 提交，不能伪造一串精确历史提交；版本目录中的 S1/S2/S3 证据等级用于区分可恢复源码、累计源码和仅有文档/测试证据的节点。云端正式版本只保留 `cloud-final-v3.2-20261022`；历史版本源码包和 Doc2 函数级查漏映射保留在公开仓库中。
