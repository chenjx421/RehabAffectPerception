# 学生名册与课堂人物关联

日期：2026-09-10。本文说明新上传视频的身份关联流程；不改变历史课堂示例的分析结果。

## 1. 需要分别解决的三件事

| 工作 | 输入与输出 | 判断边界 |
| --- | --- | --- |
| 人脸位置检测 | 当前采样画面 → 人脸候选框 | 框内可能有人脸，不说明姓名、学生/教师角色或学习状态 |
| 姓名确认 | 教师选中的画面区域 + 本校当前账号名册 → 学生编号关联 | 由熟悉学生的教师确认，可以撤销；没有把握时保留待确认 |
| 跨视频身份匹配 | 已授权并核对的参考照片库 + 新视频人脸 → 候选学生 | 需要后续独立实现与验证；本轮不会自动给陌生人贴名字 |

OpenCV 将人脸检测与人脸识别作为不同步骤提供，分别可使用 YuNet 与 SFace。此处仅接入位置检测，不能把检测分数解释成身份正确率。参考：[OpenCV 官方检测与识别教程](https://docs.opencv.org/5.0/tutorials/dnn/dnn_face/dnn_face.html)。

## 2. 第一次使用

1. 登录学校上传账号，填写城市、区县和学校。当前权限仍以账号为基础，填写相同学校名称不会使两个账号自动共享学生资料。
2. 进入学生名册，填写姓名、校内编号和班级，可补充识别备注。系统分配稳定学生编号；同名学生用校内编号及班级区分，而不是以姓名作为唯一键。
3. 上传本节课堂视频。上传页的“计划关注学生”只是课程元信息，不等于已经认出视频中的人物。
4. 处理完成后进入“确认画面中的学生”，查看带时间戳的真实采样图。系统可检测人脸候选；没有检出或画面不清楚时仍可人工框选，不能将漏检理解为学生缺席。
5. 选择一个候选或手动画框，再从本任务学校范围的名册选择学生，保存确认。教师及其他人员不绑定学生档案；不确定的人物保留为未知。
6. 保存后可重新打开核对，并下载本任务身份关联记录。错误绑定需要填写撤销原因，原始操作记录保留。

无学生名册时先创建，不自动载入历史演示中的学生。缺少学校信息、视频未就绪、原片到期或没有确认权限时，界面应显示对应状态，不产生假关联。

早期已上传视频如果没有学校快照，先展示当前账号的完整学校信息，由教师点击确认该视频归属。系统不会自动补齐；仅允许原上传者对尚无学校信息且没有任何身份绑定的任务确认一次。已有学校信息的任务不通过此入口迁移学校。

## 3. 数据怎样连起来

```text
上传账号 + 服务端保存的学校上下文
  └─ 身份名册 student_id（姓名、班级、校内编号）
       └─ 课堂视频 task_id / course_id
            └─ 处理版本 frame_revision
                 └─ 采样帧 frame_key / time_sec
                      └─ 归一化区域 bbox + 教师确认记录 binding_id
```

视频保留上传时的学校上下文快照。之后更改当前学校，不应迁移旧视频身份或让新名册自动关联旧视频。绑定必须同时验证账号权限、任务、名册范围、处理版本和有效媒体，不能仅凭客户端传入的姓名或学生编号通过。

新名册与旧演示资料分开保存，不以同名自动关联 IEP、诊断资料或五大领域报告。后续接通新校资料上传时，应由教师明确选择同一个稳定 `student_id`，并在学校权限范围内导入；不能用文件名猜测资料归属。

## 4. 本轮关联的有效范围

- 确认针对当前采样帧，不等于在整节课内自动跟踪了学生。
- 切换到其他时间点，未确认的画面仍是待确认；学生换座、离开、被遮挡或镜头切换后不沿用旧身份。
- 一张画面可确认多名学生；同帧同一学生的重复确认、明显重叠且互相矛盾的绑定应被拒绝。
- 重新处理视频后旧确认保留为历史记录，不直接套用于新版本采样图。
- 全画面运动量、亮度、声音能量仍是技术观测。即使已经确认某一人脸，也不能把全班声音归给该生，或据此直接输出其专注、情绪与掌握度。
- 帧图沿用原始视频的受控保存范围。原片到期后不再提供采样图或新的身份确认；结构化历史关联按平台规则保存，不等于允许无限期保存人脸照片。

## 5. 自动推荐姓名的后续接入条件

这一能力与当前“自动找脸”不同，需要单独增加：

1. 授权的参考照片登记入口。照片须由学校确认属于哪名学生，可以来自许可使用的清晰照片，也可以来自教师已确认的课堂截图；不能从互联网搜集学生照片。
2. 图像质量检查及重复登记复核。过小、模糊、严重遮挡或多人合影不能直接作为单人参考。
3. 本校授权范围内的特征比对。不在全平台跨学校搜人，不用班级座位、障碍类型或学习表现猜姓名。
4. 候选与拒绝机制。未达到阈值、前两名相似度接近或没有参考照片时输出“未能确定”；不承诺所有画面都有答案。
5. 与人脸识别分开的时序跟踪。跟踪用于保持同一镜头中的位置连续性；发生遮挡、换座和镜头切换时，应暂停身份沿用或重新验证。
6. 实际课堂误匹配评测。按不同课程和不同时间划分测试集，分别报告错认、漏认、待确认比例以及教师修正成本，不把公开数据集成绩当作本校准确率。
7. 参考照片及特征的删除、访问审计与授权撤回机制，再考虑减少人工确认比例。

第一次登记与确认不能完全省略，但可以由“每节课重新认人”逐步变成“系统提出候选，教师只复核不确定的片段”。

## 6. 验收与实施记录

验收使用临时数据库及虚拟名册，覆盖首次空白学校、同名学生、账号隔离、画面区域、重复与撤销、重新处理、过期媒体及管理员只读。浏览器检查同时覆盖桌面和手机。测试过程不把虚拟学生写入真实课堂档案。

本轮不接收真实人脸照片做自动姓名匹配，不建立人脸特征数据库，不改变原有会员开通和学生资料访问权限的区分。

### 本轮验证结果

- 身份存储专项：149 通过、1 跳过；跳过项为当前 Windows 权限不支持的符号链接测试。旧存储回归 78 通过。
- 人脸位置检测专项：110 通过，覆盖多视图坐标映射、去重、模型缺失及资源边界；这些是工程测试，不是学生身份识别准确率。
- 主集成运行：364 通过、1 跳过、2 个浏览器子进程超时。超时发生于并行浏览器运行期间；改为优先已安装的自动化 Chromium 并串行重跑完整界面文件后，29 项全部通过，没有放宽断言或超时上限。
- 隔离浏览器流程：原 14 组端到端检查通过；补充的旧任务学校确认 5 组检查通过，包括确认后保存、到期提示及 320px 页面操作。所有写入均使用临时数据库和虚拟学生。
- 本机真实服务：教师与管理员共 26 项只读检查通过，访问了真实采样图和检测接口，检查手机横向溢出及权限；未创建学生、未确认真实学校归属、未新增身份绑定。登录与退出会正常创建和撤销会话。

各组测试存在重叠，不相加作为独立测试总数。真实服务检查见 `output/playwright/identity_release_20260910/verification.json`，同目录保存桌面和手机截图。

### 真实素材抽查限制

已有一节真实课堂共 2,258 张采样图，采样分辨率为 640×360 且为灰度图。对固定 0、10、60、600、1,200、1,800 秒的六帧检查，YuNet 全幅检测均未给出候选；在不降低检测阈值的前提下加入重叠局部检测与去重后，候选数分别为 0、0、1、0、2、0。位置目视落在人像头部，但仍有明显漏检，且没有经过教师逐人标注评价。

这只证明本机检测与画面坐标通路可运行，不证明真实学校的自动点名已可靠。局部放大无法恢复缩图丢失的细节。若继续开发自动姓名匹配，应先接入原片高分辨率彩色关键帧，并结合授权参考照片评估人脸可用率；不要直接在现有灰度小图上承诺自动识别所有学生。
