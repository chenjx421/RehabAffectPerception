# Demo2 主线交付与后续补齐顺序

更新时间：2026-10-21

## 一、明天可测试的主线

当前云端主线已经调整为：

`登录 -> 填少量课程信息 -> 上传视频 -> 后台处理 -> 查看学生状态结果`

已完成并覆盖到云端：

- 上传完成后，任务列表首个结果入口改为“查看学生状态结果”，不再强制先进入学生名册或身份核准。
- 新增匿名人物状态结果页和接口，展示最多 3 个“人物 1/2/3”。
- 每个人按 30 秒时间窗展示参与、注意力下降、困惑/停滞、画面暂不可见等状态线索。
- 每个时间窗提供参考分、置信度、证据文字和原色证据缩略图。
- 结果页可以播放本次上传的原视频，下载本次任务的结构化结果。
- 证据帧改为 RGB 彩色保存；亮度、清晰度、运动指标仍使用灰度副本计算，避免视频被保存成黑白。
- 长视频的人脸检测采样从固定少量抽样改为每个结果窗口至少保留一个检测点，上限为 120 个采样点，避免长课大量出现人为的“暂不可见”。
- 真实测试视频已在本地完整解码，实测得到 3 个匿名人物、72 个 30 秒时间窗，人物可见覆盖约 99%、85%、74%。
- 云端应用服务已完成语法检查、备份原文件、覆盖、重启和 `/api/health` 健康检查。

本轮没有改动：数据库、上传目录、四个学校账号、管理员数据归属、邀请入口、网关和原有高级页面。

## 二、仍未完成或本轮未放入主线的功能

以下功能代码和页面仍保留，但没有作为明天测试的必经步骤：

1. **真实学生姓名与人脸的自动关联**
   - 当前结果只输出匿名人物候选。
   - 尚未验证跨时间、跨视频的稳定身份跟踪，也没有把人脸自动匹配到真实姓名。

2. **学生档案与 IEP 的自动关联**
   - 学生档案、IEP/评估资料页面保留。
   - 本轮没有把真实资料自动挂到视频分析结果，避免未经确认把敏感资料和错误人物绑定。

3. **手动画框和人工确认闭环**
   - 页面和相关接口保留，但没有作为主线要求老师先操作。
   - 还需要补充框选后的轨迹稳定性、遮挡恢复和撤销重做验收。

4. **教师标注核准对评分的正式影响**
   - 教师评分页面可以进入，当前不阻塞自动结果。
   - 尚未把教师确认片段作为正式校准标签，自动更新后续评分权重。

5. **全自动多模态大模型视频分析**
   - 当前主线使用本地视频解码、彩色证据帧、音频能量和匿名人物候选。
   - 尚未把真实学生视频直接发送给 DeepSeek、Qwen 或其他第三方多模态接口；也没有把模型输出当成已验证事实。

6. **公司后台的完整可运营数据产品**
   - 上传任务、处理状态、结果和权限查询已经存在。
   - 尚未完成长期云数据库、对象存储、备份恢复、审计报表和多学校规模化运营的最终架构迁移。

7. **视频处理加速的进一步工程化**
   - 现有云端已经做过同一真实样本的处理加速验证。
   - 当前轻量服务器仍是单 worker 串行处理，尚未做并发队列、GPU 或 COS 分片直传的正式生产方案。

8. **评分科学依据与双轨评价的最终版本**
   - 传统学校评价和系统评价的页面、规则和文献整理已有基础。
   - 尚未完成针对特殊教育课程类型的正式权重校准、近年文献审查和学校人工评分对照验证。

## 三、后续补齐顺序

### 第 1 阶段：先保证测试闭环

1. 用 4 个学校账号各上传 1 个合成或明确授权测试视频。
2. 检查上传成功、任务进入队列、状态页面刷新、分析完成、视频可播放、证据帧为彩色、结果可下载。
3. 检查一个无音频视频、一个低清视频和一个非课程视频，必须如实提示，不生成伪造的正常结论。
4. 记录每个任务的耗时、文件大小、处理状态和失败原因。

### 第 2 阶段：把匿名人物结果做成可用的学生观察

1. 先加入稳定的跨帧位置跟踪，减少人物编号在遮挡后跳变。
2. 再加入简单的手动画框、重新选择和撤销。
3. 将“人物 1”保存为本节课的匿名观察对象，并允许教师在结果页手动填写姓名，而不是先建立复杂名册。
4. 对单个学生输出本节课总结，保留时间轴明细；不是把每一帧都写入档案。

### 第 3 阶段：接入学生档案和 IEP 的最小安全版本

1. 先只保存必要字段：内部学生编号、学校、年级/班级、支持需求摘要、资料来源和有效期。
2. 原始 IEP 文件单独加密存储，不直接混入课堂结果 JSON。
3. 由教师确认“匿名人物 -> 学生档案”的关系后再归档，保留绑定人、时间和撤销记录。
4. 先做单校、单账号隔离验收，再扩大到四通道。

### 第 4 阶段：教师核准、双轨评分和科学依据

1. 教师只需核准关键片段，不要求逐帧操作。
2. 输出学校传统评分、系统增强评分和差异解释三块内容。
3. 分数采用“正常课堂不轻易拉低，明确风险事件单独提示”的规则，并对低置信度结果降权。
4. 用学校人工评价表和实际课程样本做对照，记录差异原因，不把一次测试当成准确率结论。

### 第 5 阶段：大模型和云端规模化

1. 先以脱敏关键帧、音频特征和结构化状态调用大模型，不直接上传整段真实视频。
2. API 做成可插拔适配器，模型失败时仍返回本地分析结果，不阻塞交付。
3. 对模型调用做费用、超时、重试、脱敏和审计记录。
4. 测试跑顺后再迁移对象存储、数据库和并发分析队列，最后再评估套餐和硬件销售。

## 四、当前交付边界

当前版本可以交给测试方验证“视频上传后能否产生课堂状态结果”。它还不能被描述为：真实姓名已经自动识别、IEP 已自动正确绑定、评分准确率已经验证或系统可以替代教师判断。

明天的测试重点应放在：上传是否成功、是否确实处理了本次视频、是否有 1 至 3 个匿名人物状态时间轴、画面是否保持彩色、结果是否能查看和下载。

## 六、按依赖关系逐项补齐

### 1. 先完成姓名绑定（下一项）

目标：老师看到匿名人物结果后，只做一次简单操作：点击“绑定学生”，搜索已有学生；搜不到时填写姓名并创建一个待确认档案。绑定只针对本节课和当前人物，不要求上传视频前先维护完整名册。

完成标准：

- 结果页可从“人物 1/2/3”直接进入绑定；
- 已有学生可搜索并显示学校范围；
- 新建学生只收集姓名、校内编号（可选）、年级/班级（可选）；
- 绑定记录包含任务、人物、确认人、时间和可撤销状态；
- 未绑定时仍可看匿名结果，绑定失败不影响分析结果。

### 2. 再接学生档案与 IEP 最小字段

目标：姓名绑定后进入学生档案，先保存必要摘要，不要求整份 IEP 才能分析。IEP 原文、诊断等敏感资料单独管理，按授权、来源和期限保存。

完成标准：

- 学生档案与课程结果通过稳定 `student_id` 关联，不靠姓名拼接；
- 每节课归档“本课总结 + 时间轴明细入口”，不把每一帧无限写入档案；
- IEP 只保存授权范围内的结构化支持摘要，原文不混入普通结果 JSON；
- 可查看、撤销、过期和审计绑定关系；
- 学校账号只能看到本校数据，公司后台按授权查看摘要和任务记录。

### 3. 然后接手动画框与稳定跟踪

目标：系统识别不到或遮挡时，老师在结果页对一帧画框并选择“追踪这个人”，系统把框作为当前任务的观察目标，允许撤销重做。

完成标准：

- 框选结果能在后续时间窗显示同一观察对象；
- 遮挡后恢复时不随意切换到另一名学生；
- 框选、撤销、重做和保存状态可验证；
- 画框失败时明确显示证据不足，不生成伪造状态。

### 4. 再接教师核准和双轨评分

目标：老师只核准系统推荐的关键片段，不逐帧操作。页面同时显示学校传统评分和系统增强评分，并解释差异来源。

完成标准：

- 片段、观察项、教师结论、备注和版本可追溯；
- 普通课堂分数保持合理区间，低置信度不被放大；
- 明确风险事件单独提示，不用平均分掩盖；
- 系统评分不会冒充医学诊断或替代教师判断；
- 学校人工评分样本可回放并比较差异。

### 5. 最后接大模型与生产化云端

目标：先将脱敏关键帧、音频特征和结构化状态交给可插拔模型做解释和建议，失败时继续返回本地分析；跑通后再迁移对象存储、数据库和并发队列。

完成标准：

- 模型调用有开关、超时、重试、费用上限和审计记录；
- 默认不发送姓名、IEP、诊断资料和整段真实视频；
- 模型不可用时，主线仍能完成本地结果；
- 云端数据库、对象存储、备份恢复和到期清理分别验收；
- 通过四账号、多视频、失败重试和权限隔离测试后再扩大使用范围。

## 七、操作简化原则

最终老师端固定为：

`登录 → 填课程名 → 上传视频 → 等待分析 → 查看学生状态 → 一键绑定/新建学生 → 保存本课总结`

学校端不强制先进入名册、IEP 或教师核准页面；这些功能从结果页按需进入。后台管理、资料授权、审计和双轨评分放在管理员/高级入口，不与第一次上传混在一起。
